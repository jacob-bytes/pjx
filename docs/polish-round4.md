# 第四轮 · 参考 ink 的优化（已实施）

> 依据：ink 主题仓库源码树、`docs/DetailPageRework.md`、官方预览图、
> **Playwright 视觉快照**（`tests/visual/snapshots/chromium/`）、README 设计 token 表
> 截图已存 `docs/reference/`

**重要前提**：仓库里的 `preview-detail.png` / `preview-home.png` 是**改版前**的形态；
`tests/visual/snapshots/chromium/detail-dark-mobile.png` 是**改版后**的形态，
也就是你给的 p1/p2 那一版。下面的对比以改版后为准。

## A. 详情页结构（差距最大的一块）

### A1 「4 张指标卡 + 设备信息卡」应为一张「紧凑信息摘要」卡

ink 改版后的头部是**一张卡、两列、六组键值**：

```
系统            Debian GNU/Linux …        │  CPU          AMD EPYC 7551 32-…
内存 / 硬盘      624.6 MB / 2.0 GB          │  流量         ↑ 90.0 GB · ↓ 124.0 …
                硬盘 17.2 GB / 80.0 GB      │              已用 214.0 GB / 20.00 TB
续费            USD10.9 / 年  ·  365 天     │
```

pjx 现在是 **4 张百分比指标卡 + 一张 9 格设备信息卡**，加起来占掉首屏一半，
而且 CPU/内存/硬盘三个百分比在下面每张图里又会再出现一次，属于重复。

`DetailPageRework.md` 的原文：「顶部有多张价格/指标卡，接着是硬件信息、系统信息、
存储信息、网络信息多张卡 → **移除或隐藏当前多卡片区域**」。

**收益**：首屏能提前约 300px 露出第一张图表；信息不重复。
**工作量**：半天（改 `node-detail.tsx` 头部 + `detail-section.tsx`）。

### A2 横轴改成真实时间戳

ink 的图横轴是 `19:01 19:11 19:21 …`，pjx 是「1 分钟前 / 30 秒 / 现在」。

相对跨度在实时档还行，但切到 7 天档时「3.5 天前」远不如一个具体日期好读 ——
运维看曲线第一反应是"这是什么时候的事"。数据层已经有 `lastReport`，
往前推算即可，不需要新数据。

**工作量**：1 小时。

### A3 时间范围补「30 天 / 自定义」

ink：`实时 4小时 1天 7天 30天 自定义`；pjx 只有前四个。
`RANGES` 已经是数据驱动的，加档位是纯配置；「自定义」需要个日期区间选择器。

**工作量**：30 天档 20 分钟；自定义 2 小时（要引入日期选择）。

### A4 头部补节点选择器下拉

ink 头部是 `‹ [节点名 ▾] ›` —— 中间那个是**下拉选择器**，可以跳任意节点。
pjx 只有前后切换，12 台还行，200 台就不好用了。

**工作量**：1 小时（用现成的 `DropdownMenu` + 搜索）。

### A5 去掉面积填充

`DetailPageRework.md`：「去掉大面积 areaStyle / 渐变」「线宽统一变细」。

pjx 现在 7 张图里 5 张开了 `fill`。ink 是纯线条 + 极细网格。
去掉填充后曲线更利落，而且叠线时不会互相糊。

**注意**：这条与"灵动"有张力 —— 面积填充是现在主要的视觉重量来源。
建议**只在多序列图上关**，单序列保留。

**工作量**：30 分钟。

### A6 图表区分组 + 弱化卡片容器

ink：`轻量 Tab：资源 / 网络延迟`，`LoadChart 单列分节，弱化卡片容器`。

pjx 现在是 3 列卡片网格，一页铺 7 张卡（CPU与负载 / 内存与Swap / 磁盘 /
实时网络 / 网络连接 / 进程 + ping）。手机上要滑很久。

建议：Tab 分「资源 / 网络」两组，资源组单列分节（去掉卡片边框，用分隔线），
网络组放 ping。

**工作量**：半天。这条改动最大，但也是收益最大的。

### A7 ping 任务卡改轻量列表 / pill

ink：「任务统计卡改为轻量列表 / pill」「去掉大卡片 hover 变色」。
pjx 现在是 6 张带边框卡片。

**工作量**：1 小时。

## B. 总览页

### B1 筛选栏补排序项与计数

ink 的筛选栏：`全部节点 | 生产 | 测试,边缘 | ☆收藏 0 | ⇅流量 12 | ⇅峰值 12 | ⇅离线 1 | ⇅高负载 1 | ⇅即将到期 1`

每项**带计数**，而且「流量 / 峰值 / 离线 / 高负载 / 即将到期」是**排序入口**。

pjx 只有分类筛选 + 两个只读统计。加排序是实打实的可用性提升 ——
30 台机器时"按流量排序"比"逐个看卡片"有用得多。

**工作量**：半天。

### B2 节点卡补负载三元组与绝对值

ink 卡片每行是 `CPU 8.0% [进度条] | 内存 28.0%`，下一行 `0.18, 0.14, 0.10, 0.14`（负载三元组）。

pjx 的负载三元组埋在 CPU 的 detail 小字里。提到独立一行更符合"运维一眼看负载"的习惯。

**工作量**：1 小时。

## C. 能力层（ink 有、pjx 完全没有）

### C1 背景可配置 + 卡片毛玻璃 ⭐

这是 ink 的**招牌能力**，也是我这轮才发现的：官方快照里详情页是
**彩色渐变背景 + 半透明毛玻璃卡片**（`src/components/Background.vue` +
`scripts/assets/glass-admin.css`）。ink 的 46 项后台配置里专门有一组「背景」。

对应到 pjx：`--background` 从单色改成可切换的渐变/图片，卡片走半透明 + `backdrop-blur`。
**这是"气质"层面最大的一个增量**，比任何单个组件的打磨都显眼。

要权衡的：`backdrop-filter` 有性能成本（尤其移动端叠加 7 张图时），
且必须保证毛玻璃上的文字对比度仍达标（我们有 `check:contrast` 脚本，可扩展成
"在给定背景上复核"）。

**工作量**：1–2 天（含对比度回归与性能验证）。**建议单独一轮做。**

### C2 卡片网格虚拟滚动

ink 有 `src/composables/useVirtualCardGrid.ts`。pjx 前端 12 张卡无所谓，
但规范写的是 ≤200 台 —— 那时 200 张卡片（每张 ~30 个节点）会明显卡。

**工作量**：半天。**建议等真实数据接上、真的到 100+ 台再做**，现在做是过度设计。

### C3 触控目标 ≥44px

ink README 明确写「触控 ≥44px」。pjx 上一轮做到 32px 就停了（我当时判断
再往上会破坏 13–14px 的数据密度）。ink 证明了两者可以共存 —— 它用
"图标小但留白大"的方式达成，不是把图标画大。

**工作量**：2 小时（主要是调间距而不是改尺寸）。

### C4 色觉友好模式

ink README：「色觉友好模式保留全彩」。即提供一个开关，把状态色换成
"色相 + 形状/图案"双通道。pjx 已经在图表线上做了线型双通道，
但状态点、进度条还是纯色。

**工作量**：半天。

## D. 工程实践

### D1 Playwright 视觉回归 ⭐

ink 有 `tests/visual/visual.spec.ts` + 3 张 chromium 快照 +
`.github/workflows/visual-regression.yml`。

**pjx 现在一张视觉快照都没有** —— 我这三轮全部靠 headless 数 DOM 元素、
量坐标、比路径字符串来验证。这种方法能证明"没坏"，但证明不了"没变丑"。
前面 A3 那次配色翻车（6 条线几乎同色）就是数 DOM 数不出来的，最后靠肉眼截图才发现。

**这是所有条目里最该补的一个** —— 它保护的是前三轮所有工作的成果。

**工作量**：半天（`@playwright/test` + 4 个快照即可）。

### D2 不引入 ECharts

ink 用 `vue-echarts`（ECharts 6 按需树摇）。但 ink 是 Vue，且它的图表需求
（双轴、自定义 tooltip、多设备 GPU）比 pjx 重。pjx 自研 SVG 组件在
≤200 点/图的量级完全够用，引库要 +30~80KB gzip 并丢掉 token 联动。
**建议维持现状**，除非将来要加缩放/框选。

## E. 实施记录

### D1 Playwright 视觉回归 ✅

先铺安全网，后面所有改动才有得验证。

- `@playwright/test` + **系统 Chrome**（`channel: "chrome"`，省掉 ~150MB 浏览器下载）
- 8 张基线：公网列表 / 详情浅色 / 详情深色 / 详情移动端 / 极光背景 / 暮色深色 /
  后台总览 / 后台 Sheet
- `npm run test:visual` / `npm run test:visual:update`

**让截图可复现的两个前提**（缺一个快照就永远对不上）：
1. `Math.random` 换成定种子的 LCG（mock 的曲线、节点状态全靠它）
2. `page.clock.install()` 冻结时钟（头部时钟、`lastReport`、30 天时间轴日期）

#### 定这套阈值踩过的四个坑（都写进 `playwright.config.ts` 注释了）

| 坑 | 现象 | 修法 |
| --- | --- | --- |
| vite 绑 `localhost` 可能只绑 `::1` | webServer 等到 120s 超时 | 显式 `--host 127.0.0.1` |
| 截图前没等自托管字体 | 全页每个字形边缘零点几像素差异，6 张里 5 张失败 | `document.fonts.ready` + 两帧 rAF |
| 时钟推进放在 `goto` 之前 | 快照定时器还没注册，偶发失败 | 移到 `goto` 之后 |
| **`reuseExistingServer: true`** | **复用已跑的 preview 会跳过 `npm run build`**，改了源码测的却是旧产物 —— 改错了也显示"通过"，我被骗过两次 | 设成 `false` |

#### 阈值怎么定的（实测，不是拍脑袋）

列表页有 **2300~2900 像素**的亚像素抗锯齿噪声底（1px 级进度条与直方图落在不同
子像素边界上；两次渲染的 `innerText` 完全一致、字体全 loaded，确认不是数据问题——
为此把 `MiniBars` 从 40 个 `flex-1` 的 div 换成了固定 viewBox 的 SVG）。

而改一个品牌色只有约 3200px —— **和噪声同量级，分不开**。

所以最终取 `threshold: 0.35` + `maxDiffPixels: 3500`（刚好高于噪声底），
并明确职责边界：

> 本套件抓**结构性回归**。实测把 KPI 从 4 列改成 3 列会产生 **58,923 像素**差异
> （阈值的 17 倍），删掉整个区块同样必失败。**小幅配色微调它抓不到** ——
> 配色由 `npm run check:contrast` 在 token 层面用数值保证。

### A2 真实时间戳 ✅

横轴从「1 分钟前 / 30 秒 / 现在」改成 `22:28 / 22:29 / 22:30`。
新增 `formatAxisTime(date, span)`，按跨度选粒度：一小时内到分钟、超过一天带月日。
实测渲染出 `22:28, 22:28, 22:29`。

### A3 补 30 天 / 自定义 ✅

`RANGES` 加 `30d`（180 点）与 `custom`；自定义用两个原生 `<input type="date">`。
`custom` 的跨度参与缓存 key，否则改日期会拿到旧数据。

### A4 节点选择器 ✅

头部节点名变成可点开的选择器：搜索框 + 过滤列表，外点 / Esc 关闭。

**这里走了弯路**：第一版用 cmdk 的 `CommandDialog`，功能没问题，但**把 cmdk 拖进了
前台包** —— 共享 chunk +25KB gzip，前台首屏从 102.7 涨到 127.3 KB。
为了一个节点选择器付这个代价不值得，改成零依赖的轻量面板。

### A5 多序列去填充 ✅

规则：**≥2 条非参考线才去填充**。实测全页只剩 2 处面积填充（磁盘、进程，都是单序列）。

### A1 紧凑信息摘要 ✅

4 张百分比指标卡 + 9 格设备信息卡 → **一张卡的 4 列紧凑栅格**（系统 / CPU / 内存 /
硬盘 / 流量 / 负载 / 运行时长 / 续费），容量类指标保留细进度条。
首屏大约提前 300px 露出图表。删掉了已无引用的 `MetricTile` / `InfoCell`。

### A6/A7 图表分组 + ping 轻量列表 ✅

「资源 / 网络延迟」两组切换；ping 从带边框卡片改成**轻量 pill**，色块按线型渲染
（与折线一一对应）。

**同样为了体积**：第一版用 `ui/tabs`（Radix Tabs），会给前台再加约 6KB gzip，
改用自带的 `Segmented` —— 两组互斥切换，语义完全够。

### B1/B2 总览页 ✅

- B1 排序 chips：默认 / CPU / 内存 / 流量 / 延迟 / 剩余天数，进 URL（`?sort=`），
  离线节点一律沉底（排序是为了找"最忙的"，不是把断线的排最前）
- B2 负载三元组提到独立一行，右侧带连接数

### C1 可配置背景 + 毛玻璃 ✅

- 4 档：纯色 / 极光 / 暮色 / 暖阳，`localStorage: pjx-background`
- 背景走 `body::before` 的固定装饰层，**不动 `--background`** —— 后者被 sticky 头部、
  popover 当纯色用，换成渐变会直接坏
- 卡片毛玻璃用一条 `html[data-bg] .bg-card` 规则统一接管（优先级高于单类，不用改组件）
- 尊重 `prefers-reduced-transparency`
- 选择器：后台设置页 + 前台顶栏紧凑切换按钮

**对比度要专门验**：毛玻璃上的文字等于"卡片色 × alpha 叠在渐变上"，
`check-contrast` 扩展了这一段 —— 取渐变两端做最坏情况，在 sRGB 空间按 alpha 合成。
结果：最差 4.92:1（aurora 浅色），六种组合全部达标。

### C3 触控 ≥44px ✅

ink 的做法是"图标小但留白大"。用 `@custom-variant touch (@media (pointer: coarse))`
把命中区撑到 44px，**桌面保持 32px 紧凑**，数据密度不变。

### C4 色觉友好模式 ✅

状态指示从"只有颜色"变成"颜色 + 形状"：在线圆、告警三角、严重方块、离线短横
（`clip-path` 实现，尺寸与对齐不变）。开关在后台设置页。

顺带修了一个真问题：节点卡的状态点原来是裸 `<span>`，**既没有形状通道也没有
aria-label**（对读屏完全沉默），改成复用 `StatusDot`。

### 顺带修

- `lastReport` 首帧为空 → 详情页在第一次 tick 前显示「最后上报 —」，改成模块加载时就有值
- `scrollbar-gutter: stable` → 内容变长时页面不再横向跳一下

## G. 第五轮：四项调整

### 1. KPI 卡压缩 ✅

- 删掉「实时速率」卡底部的「上行 + 下行合计」文字（`footer` 改为可选 prop）
- 内边距 `p-4 → p-3.5`，数值 `26px → 24px`，sparkline `h-10 → h-7`，各段间距收紧
- 整排高度跟着最矮的那张走，视觉上与 p2 的目标形态一致

### 2. 十字游标 + 消除卡顿 ✅

**卡顿的根因不是渲染慢，是每帧都重渲染**：原来每次 `pointermove` 都 `setState`，
触发整张图重渲染并重建全部路径（最多 180 点 × 6 条线）+ 网格 + 刻度。

改成**命令式**：十字游标、序列点、两个轴气泡、tooltip 全部用 `ref` 直接改 DOM，
hover 期间 React 一次都不渲染。触屏的"点一下锁定"也用 `ref` 存状态，避免为此重渲染。

游标形态按 p4 补齐：
- 竖线（时刻）+ **横线（数值）** 双轴锁定
- 各数据序列上画点（参考线不画）
- **左轴数值气泡** + **下轴时刻气泡**（深色圆角块反白文字）
- tooltip 列出全部序列的值

### 3. 图标柔化 ✅ 已整体换 Phosphor

**Lucide → Phosphor 全量迁移**（确认后执行）：

- 23 个文件 / 24 处 import / 46 个不同图标全部替换
- 全局 `IconContext` 设 `weight: "light"`（比默认 regular 更柔和），
  不必逐个传 weight；尺寸仍由 Tailwind 的 `size-*` 类控制（CSS 覆盖 svg 属性）
- 移除 49 处 `strokeWidth` 与旧的 `.lucide` CSS 规则
- 映射表里几个不存在的名字做了就近替换：
  `Activity → Waveform`、`Radar → Broadcast`、`SearchX → MagnifyingGlass`、
  `Waypoints → ShareNetwork`、`MoreHorizontal → DotsThree`

**迁移中必须注意的一点**：Phosphor 是**填充式**图标（`fill="currentColor"`），
不是描边式。原来星标用 `fill={favorite ? "currentColor" : "none"}` 表达空心/实心，
换过来后 `"none"` 会让图标**整个消失**。4 处全部改成

## I. 第七轮：三处修正

### 1. 轴气泡没包住时间 ✅

**根因**：两个轴气泡的宽度是**写死的**（时刻气泡 50px、数值气泡 40px），
而 `formatAxisTime` 在 30 天档会输出 `12-18 22:08` —— 10px 等宽下约 65px，直接溢出。

**修法**：新增 `fitBox()`，用 `getBBox()` 量渲染后的**真实**文字宽度再撑开背景，
并重新居中。不是按字数估算 —— 等宽字体里数字 / 冒号 / 汉字的宽度并不一致，
估算一定差几个像素。

实测（30 天档，hover 在延迟趋势图）：

| 气泡 | 文字 | 文字宽 | 气泡宽 |
| --- | --- | --- | --- |
| 左轴 | `39` | 11.8px | 40px（走最小宽度） |
| 下轴 | `12-18 22:08` | 64.9px | **76.9px**（旧版 50px，溢出 15px） |

### 2. 工具栏的「高负载」与排序箭头 ✅ 已删

- **「高负载 n」**：和上面的「高负载节点」KPI 卡是同一个数字，纯重复 → 删除。
  「即将到期 n」保留（KPI 卡里没有这一项）。
- **排序前面的 ⇅ 图标**：纯装饰，六个排序项的文字本身已经说明用途 → 删除。

### 3. 状态通栏可关闭 ✅

选择**加关闭按钮**而不是整条删除：状态通栏是公网状态页回答"现在有没有问题"的
那一句话，删掉会让页面回到"要自己找 6px 圆点"的状态。

- 右上角加关闭按钮（触屏下命中区 44px）
- 关闭状态**只存在组件 state，不进 localStorage** —— 刷新页面会重新出现，
  正好是你要的"每次进来只显示一次"

## J. 第八轮：三处修正

### 1. 轴气泡（摘了桃子丢西瓜）✅

上一轮只修了**横轴**气泡，纵轴那个从没验证过 —— 这次一并修完并写了穷举测试。

**纵轴气泡其实有两个独立问题**：

1. **位置错了**：气泡组只做了 Y 平移、没有 X 平移，而 rect 以 `x=0` 为中心，
   等于跨在画布左边界上，一半画在画布外 → 数字被裁。
   修法：让它落在左轴刻度区，中心 `Y_CALLOUT_CX = (AXIS_W - 6) / 2`。
2. **长数值仍会向左溢出**：固定居中时，`1.6 GB` 这种文字宽 36px、气泡 48px，
   左边缘到 -4。修法：气泡比刻度区还宽时改成左对齐（`cx = max(w/2, Y_CALLOUT_CX)`）。

**顺带抓到第二个同类 bug**：穷举测试发现横轴气泡在贴近**右端**时会越出画布右边
（`right=603.5 > 577`）。这是同一类错误的另一半，如果不写穷举测试根本发现不了。

**这次的验证方式**：写了一个穷举测试，遍历 **6 张图 × 6 个指针位置**，
逐次读取两个气泡 rect 的 `getBoundingClientRect()` 与文字的 `getBBox()`，
断言「气泡宽 ≥ 文字宽」且「左右边界都在画布内」。跑通后删除。

> 教训：上一轮修完横轴就以为完事，实际是"修了一个实例，没修这一类"。
> 现在的做法是把这一类问题写成可执行的断言，而不是看一眼截图。

### 2. 延迟/丢包直方图 ✅

**问题**：40 根 1.6 宽 × 8 高的细条挤在约 114px 里，一眼看过去像打了马赛克。

**改法**（对齐 p3）：

| | 改前 | 改后 |
| --- | --- | --- |
| 格数 | 40（每秒一格） | **20**（每两格取最大值 —— 延迟/丢包关心峰值） |
| 形态 | 1.6 宽 × 8 高（瘦高） | **约 4 宽 × 6 高**（矮粗），容器 `h-2 → h-1.5` |
| 颜色 | `ok/50` `warn/80` `crit/70` | **`ok/80` `warn/90` `crit/85`**（加深） |
| 交互 | 无 | **hover 显示数值 + 「N 秒前」**，并补了 `sr-only` 文本给读屏 |

hover 用「跨越格子才 setState」，不是每帧更新 —— 20 格最多重渲染 20 次，
不会把整张卡拖垮。

### 3. 分类 + 排序控件 ✅

**问题**：两组都是纯文字按钮挨在一起，扫过去分不清哪个是"筛选"哪个是"排序"，
激活态也只是变个颜色。

**改法**：
- 分类的激活态从"只变色"改成**实心胶囊**（`bg-accent`），配 `aria-pressed`
- 排序套一层**分段容器**（边框 + 内衬），和左边在视觉上明确分开
- 两者都补了 `role="group"` + `aria-label`，触屏下高度撑到 44px

### 验证

`tsc -b` / `build` / `check:contrast` 全绿；视觉回归 6 张、2 连跑全绿。

## Q. 第十五轮：字体换成 Plus Jakarta Sans

### 先查清了 ink 用什么

```css
--font-sans: 'Inter Variable', ui-sans-serif, system-ui, -apple-system, sans-serif;
```

用 `@fontsource-variable/inter`（**可变字体**，一个文件含全部字重）。

### 但「板正 vs 圆润」其实是两个原因

查 ink 的数字排版时发现了更关键的一处：

| | ink | pjx（改前） |
| --- | --- | --- |
| 西文 | Inter Variable（1 个可变文件） | IBM Plex Sans（3 个静态文件） |
| 数字 | `font-mono` → **系统等宽**（0 KB） | `font-mono` → JetBrains Mono（2 个文件） |
| 下载合计 | 47 KB | **111 KB** |

**ink 根本没装等宽 webfont** —— `font-mono` 直接落到系统等宽。

所以 pjx 的"板正"来自两处叠加：

1. **IBM Plex Sans** 笔画末端带斜切角，气质偏工程化
2. **JetBrains Mono** 极技术感 —— 而全站 `.num` 用了 100+ 处，
   **数字是这个界面里最显眼的东西**，这是主因

### 选型：Plus Jakarta Sans（不是 Inter）

Inter 就是 ink 那套，但**它是当下"AI 味"最重的字体**，几乎每个 AI/SaaS 产品都用它 ——
选它等于用「去AI化」换「像 ink」。Plus Jakarta Sans 同样是圆润的几何风格，
但没那么烂大街。

### 改动

- `--font-sans`：IBM Plex Sans → **Plus Jakarta Sans Variable**
- `--font-mono`：JetBrains Mono → **系统等宽栈**（照 ink 的做法）
- 移除 `@fontsource/ibm-plex-sans`、`@fontsource/jetbrains-mono` 两个依赖

### 效果

| | 改前 | 改后 |
| --- | --- | --- |
| 西文 | 69 KB（3 个静态字重） | **26.7 KB**（1 个可变文件，含 200–800 全字重） |
| 数字等宽 | 42 KB（2 个文件） | **0**（系统等宽） |
| **字体总下载** | **111 KB** | **26.7 KB** |

**省 84 KB（−76%）**，字体从"和整个 JS 一样重"降到 JS 的 1/4。

> 顺带修正了字重覆盖：可变字体含 200–800，而之前的静态文件只有 400/500/600 ——
> 万一将来用到 700 会触发浏览器伪粗体，现在不会了。

### 验证

`npm run verify` 全绿（类型 + 对比度 + 12 张重跑的视觉基线）。

## R. 第十六轮：上一轮扫描剩下的四项

### 1. 数值微高亮 ✅（最大的「灵动」缺口）

盘点发现全站 26 处动效里 **23 处是颜色过渡**，而这是个每秒刷新的面板 ——
**数字是硬跳的**。新增 `FlashValue`：值变化时做一次 500ms 的淡出底色。

两个刻意的选择：

- **用 Web Animations API 而不是 React state**。12 张卡 × 4 个指标，
  每秒可能触发几十次；走 setState 会把整页重渲染拖垮。
  `element.animate()` 不触发渲染、不占 React 树、结束自动回收。
- **只做底色淡出**，不做位移、不做滚动数字。之前明确否决过"卡片入场动画"那类花活，
  这条不是它 —— 它只在**值真的变了**时响应。

实测：**3.5 秒内触发 72 次**。抓帧看下来是「整片数据在轻轻呼吸」，
而不是每个值各闪各的 —— 因为这个页面几乎每个值每秒都在变。
所以它的语义是**「数据刚刷新」的脉冲**，而不是「这个值变了」的定位器。
我认为这个语义在监控面板上更有用（一眼知道页面是活的），但如实记在这里。

挂接位置：节点卡 4 个指标值 + KPI 的「累计流量」「实时速率」。
**在线节点 / 高负载节点故意不加** —— 它们变化很慢，闪一下反而是噪音。

### 2. 手写按钮收口 ✅（20 → 10）

先分类再动手 —— **不是所有 20 个都该变成 shadcn Button**：

| 类型 | 处理 |
| --- | --- |
| 图标按钮（返回 / 上一下一个 / 星标 / 关闭通栏） | ✅ 收进 `IconButton`（底座是 shadcn Button ghost+icon） |
| 胶囊切换（分类、后台标签） | ✅ 收进 `ToggleChip` |
| 分段项 / 时间轴格子 / 下拉选项 / 复杂 ping 胶囊 | **保留手写** —— 它们是结构性子元素，套通用按钮反而错 |

`IconButton` 直接吃 shadcn 的 ghost 变体：它的 hover 色（`--accent`）与原来手写的
`--muted` 只差 **0.017 明度**，视觉几乎无变化，但白拿了 focus-visible 环、
disabled 语义，以及"所有图标按钮长得一样"。

`ToggleChip` 做了 **filled / raised 两种选中态** —— 不能合并：分段容器本身是灰底，
容器内的选中项再用实心底就没有层次了。

### 3. 三套手写 tooltip 统一外观 ✅

时间轴、延迟直方图、折线图各写了一套气泡，三份外观定义各自维护。
抽出 `tooltipShell()` —— 注意是**函数**不是组件：折线图的游标气泡用 ref
直接改 DOM（hover 期间零重渲染），渲染不出 React 组件，只能共用同一份 class。

只统一**外观**，定位仍由使用处给：三个气泡的锚点逻辑（贴顶 / 贴底 / 跟随游标）
本来就不同，强行统一会互相将就。

### 4. 两个小项 ✅

- `heartbeat.tsx` 的 `transition-all` → `transition-colors`
  （shadcn 上游的 3 处保留，改了会与 `shadcn add` 冲突）
- 删除零使用的 `--text-xl`（20px）—— 死 token

### 验证

`npm run verify` 全绿（类型 + 对比度 + 12 张重跑基线），2 连跑稳定。

## S. 第十七轮：撤掉微高亮、收紧卡片顶部、换成 Inter

### 1. 移除数值微高亮 ✅（实测后否决）

上一轮加的 `FlashValue`（值变化时 500ms 淡出底色）**实际观感不对**，撤掉。

复盘为什么判断错了：我看到的"整片数据在呼吸"在静态抓帧里成立，
但动态下每秒一次、十几个数字同时闪，读起来是**干扰**而不是"灵动"。

> 教训：**动画类改动不能用静态抓帧评估**。我当时只看了单帧就下了结论，
> 而动画的问题恰恰只在时间里才暴露。以后这类改动应该直接交给使用方看动态效果，
> 而不是自己看截图拍板。

撤销范围：删除 `flash-value.tsx`、`--flash` token、KPI 的 `flashKey` prop 与两处挂接、
节点卡指标值的包装。全部还原。

### 2. 卡片顶部留白收紧 ✅

先量再改。卡片上沿到服务器名的距离**实测 20.8px**，但拆开看主因不是内边距：

| 组成 | 值 |
| --- | --- |
| 卡片 `padding-top` | 14px |
| h2 行高的半行距 | ~4px |
| **收藏按钮在 flex 行里把行高撑到 32px** | **~8.5px** ← 主因 |

那个收藏按钮是 `size-8`（32px 命中区），而旁边的文字行只有约 15px ——
`items-center` 让文字在 32px 的行里居中，上下各多出约 8px 空白。

改法：
- 收藏按钮加 `-my-2`：**命中区仍是 32px，但不再撑高标题行**
- 卡片 `p-3.5` → `px-3.5 pt-2.5 pb-3.5`
- h2 加 `leading-tight`

结果：**20.8px → 11.0px（−47%）**，单张卡高度 341 → **328px（−13px）**。

### 3. 西文换成 Inter ✅（对齐 ink）

`Plus Jakarta Sans` → **Inter Variable**，与 ink 完全一致。
数字维持系统等宽（上一轮已改成这样）。

| | 改前 | 改后 |
| --- | --- | --- |
| 西文 | Plus Jakarta Sans（26.7 KB） | **Inter Variable（47.1 KB）** |
| 数字 | 系统等宽 0 KB | 系统等宽 0 KB |
| 合计 | 26.7 KB | **47.1 KB** |

比 Plus Jakarta 重 20 KB，但仍比最初的 111 KB 省 64 KB。

实测确认：节点名 `font-family: "Inter Variable", "PingFang SC", …`，

> 取舍记录：Inter 是当下最普遍的 SaaS/AI 字体，选它是在

## T. 第十八轮：卡片「在线 43d 在线」

### 表面问题是重复，实际是两个 bug

p1 里节点卡第二行显示「在线 43d 在线」—— 同一个词出现两次。查下去发现不止：

```tsx
<span className="text-subtle">在线 {node.uptime}</span>   // ← 写死的「在线」
<span className={statusTone}>{statusText}</span>          // ← 也是「在线」
```

1. **重复**：在线节点两处都渲染「在线」
2. **前半句的「在线」是写死的** —— 告警节点实际显示成 **「在线 31d 告警」**，
   离线节点会显示成「在线 — 离线」。这是内容错误，不只是难看

### 修法

拆成两件互不重叠的事，且在任何状态下都成立：

| 状态 | 改前 | 改后 |
| --- | --- | --- |
| 在线 | 在线 43d 在线 | **运行 43d 在线** |
| 告警 | 在线 31d 告警 ← 错 | **运行 31d 告警** |
| 离线 | 在线 — 离线 ← 错 | **— 离线** |

「运行时长」是中性事实，「状态」是判定结果 —— 原来的写法把判定结果混进了事实里。

### 验证

用 Playwright 遍历首屏 12 张卡，打印每张的状态点 `aria-label` 与元信息行，
确认三种状态下的文案都正确（截图看不出的告警态在这里被覆盖到）。

`npm run verify` 全绿（类型 + 对比度 + 12 张重跑基线）。

## W. 第二十一轮：页脚重构

按评审意见把页脚从"一行文字平铺"改成"左右双栏 + 文本阶梯 + 状态指示"。

### 1. 左右双栏解耦 ✅

```
[左] Powered by pjx · © 2026        [右] 仅展示公开指标 · ● 最后同步 22:33:40
```

左侧是**品牌与版权**（静态、低频），右侧是**数据状态与同步时间**（动态、每次刷新都变）。
原来用「·」把六段文字串成一行，读起来是一堆同级信息平铺 ——
既看不出主次，也分不清哪块是"关于这个站"、哪块是"现在的状态"。

窄屏自动堆叠成两行。

### 2. 文本阶梯 ✅

原来全页脚同一字号同一灰度。实测计算值：

| 元素 | 颜色 | 明度 | 字重 |
| --- | --- | --- | --- |
| `pjx` | `oklch(0.235 …)` | **最暗** | 500 |
| `© 2026` | `oklch(0.505 …)` | 中 | 400 |
| `仅展示公开指标` | `oklch(0.536 …)` | 最浅 | 400 |

### 3. 状态指示灯 ✅（但没加脉冲）

用与顶栏「实时」**同一个 `StatusDot`**，放在「最后同步」前面。

**没有按建议加呼吸动画**，两个理由：

1. 顶栏的实时指示灯是静态的，页脚再做一个会闪的就不一致了
2. **ink 自己的原则**写在它源码注释里：
   > 「呼吸动画仅用于离线告警：健康节点保持静态，避免网格中大量卡片同时闪烁的噪音感」

健康的绿点一直在闪，本身就是噪音。而且上一轮刚因为同样的理由撤掉了数值微高亮。

### ⚠️ 一条没有照做的建议：`#94A3B8`

评审建议次要文字用 `#94A3B8`。实测：

| 颜色 | 在我们的背景 `#f4f6f8` 上 |
| --- | --- |
| `#94A3B8`（建议值） | **2.37:1 — 低于 AA 4.5:1** |
| `--fg-subtle`（现用） | 4.74:1 ✓ |
| `--muted-foreground`（现用） | 5.42:1 ✓ |

`#94A3B8` 是 Tailwind `slate-400`，在白底上做正文本身就偏浅；

## AA. 第二十五轮：丢包事件带 + 探测周期模型

### 1. 丢包事件带 ✅

`TimeSeriesChart` 新增 `bands` 能力：绘图区底部的窄条，按强度决定高度。

**为什么不做成第二条曲线**（上一轮的分析结论）：延迟是 ms、丢包是 %，
双 Y 轴的"相关性"完全取决于两个轴怎么缩放 —— 同一份数据把丢包轴放大两倍
看起来就"强相关"。事件带不引入第二个刻度，只回答"哪一刻出过事"。

调参过程记录（**每一轮都是量出来才改的**）：

| 轮次 | 现象 | 原因 | 处理 |
| --- | --- | --- | --- |
| 1 | 59 根等高的条，像虚线 | mock 里每条线路 12% 的点有丢包，6 条并集 **45%** | 概率降到 3% → 并集约 13% |
| 2 | 0 根 | 阈值定 0.2，而实测非零值域只有 0.05~0.4 | 阈值调到 0.05 |
| 3 | 27 根，高度全挤在 2~3px | 归一化上限定 1，而数据最大才 0.4 | 上限调到 0.3 |

最终 **8 根 / 60 点（密度 13%）**，彼此分开，能读出"事件"。

> 这里有个更根本的修正：**mock 原来把丢包建模得太频繁了**。
> 12% 的采样点丢包在真实网络里是灾难级的。改数据不只是为了好看 ——
> 原来那版会让人误以为丢包是常态。

### 2. 延迟探测周期 ✅（这是模型问题，不只是 UI）

原实现把延迟/丢包当**实时数据**处理（1Hz × 60 点，档位里有「实时」）。
实际上探测按固定周期跑，否则数据库会被打爆：一台机 6 条线路，
100 台就是每秒 600 行。

新增 `PING_INTERVAL_SECONDS = 90`（后台可配，常见 60/90/180），并连带修正三处：

1. **档位去掉「实时」** —— 数据本身不是实时的，给个实时档是撒谎。
   换成 `PING_RANGES`：1 小时 / 6 小时 / 1 天 / 7 天 / 30 天
   （ink 的弹窗同样是 1小时/6小时/12小时/1天/7天，**没有实时**）
2. **点数按探测周期换算** —— 30 天按 90 秒一次是 28800 个采样，不可能全画。
   每个展示点是**一个时间桶的聚合**（延迟取桶内均值、丢包取桶内比例）
3. **界面标出探测周期** —— 弹窗副标题写明「90s 一次探测」。
   用户必须知道那个"最新值"最多可能已经 90 秒旧了

资源类图表（CPU/内存/磁盘/流量）**不变** —— 那些确实是每秒采一次。

## AB. 第二十六轮：延迟值按周期稳定 + 事件带图例

### 1. 延迟值还在每秒跳 ✅（真 bug）

上一轮加了 `PING_INTERVAL_SECONDS`，但**只改了档位和点数，没改每 tick 的更新** ——
`tick()` 里仍然每秒 `node.latency += random`。界面上那个"最新延迟"每秒跳一次，
而它实际是 90 秒前的探测结果。

修法：把延迟/丢包/ISP/ping 的更新搬进**按周期判定的分支**：

```ts
const probeEpoch = Math.floor(updatedAt / (PING_INTERVAL_SECONDS * 1000))
if (probeEpoch !== lastProbeEpoch) { … 更新 … }
```

**过程中踩了一个坑**：第一次改完仍然在跳。因为原来那处 `node.latency = …`
有两份（一份在 tick 主流程、一份在刚加的周期分支里），我的删除只匹配到一份，
于是**每 tick 的旧代码还在跑**。tsc 不会报「同一变量被赋值两次」这种问题 ——
是靠"改完仍有症状"才回去逐行看的。

实测确认：

```
起点(正好在周期边界) = 42
跨过 1 个周期后      = 45
再走 80 秒后         = 45   ← 周期内稳定
```

> 顺带说明为什么测试要绕一下：`FIXED_TIME` 是 `2026-01-01T12:00:00Z`，
> 而 `1767268800 / 90 = 19636320` **整除** —— 起点恰好压在周期边界上，
> 一开始推进 30 秒就跨了一个周期，看起来像"还在实时变"。
> **是测试窗口选错了，不是代码错。**

### 2. 弹窗默认显示延迟 ✅

去掉了"按点击的小块预选页签"的逻辑，打开就落在延迟。

## AH. 第三十二轮：移动端适配（第一轮：修实测溢出的部分）

```
文本「MB/s」  右=438
```

**根因**：`↑ 10.7 · ↓ 7.88 MB/s` 用固定 `text-2xl`（24px）需要约 310px，

| 位置 | 改前 | 改后 |
| --- | --- | --- |
| 头栏副标题 | `服务状态` 常显（窄屏换行） | **`hidden sm:inline`** |

| KPI 数值 | 固定 `text-2xl` | **`text-sm sm:text-lg md:text-2xl`**（取值与 ink 一致）|
| 实时速率的 `·` | 常显 | **窄屏隐藏**，间距 `gap-1 sm:gap-1.5` |

### 结果（实测）

| | 改前 | 改后 |
| --- | --- | --- |
| 视口外溢出的元素 | 2 | **0** |
| 头栏高度 | 换行（>49px） | **49px 单行** |
| KPI 实时速率值 | 被裁（`↓ 7`、`MB/s` 缺） | **143/143px 完整**（390 / 768 / 1280 三档都完整）|

## AL. 第三十六轮：修复上一轮对桌面端的破坏

### 我犯的错

上一轮用 `sm:contents` 做时间轴端点适配，**移动端对了，桌面端坏了**：
`8月14日 9月12日` 挤在左边，而不是"起始日 ─ 图例 ─ 结束日"分居两端。

**根因**：`sm:contents` 让外层 span「化掉」后，结束日在 DOM 上排到了图例**前面**。
而 `ml-auto` 只能把它**之后**的元素推到右边 —— 所以被推走的是图例，
结束日反而留在了左边。

```
DOM:  [起始日] [结束日] [图例 ml-auto]
视觉:  12月3日  1月1日  ..............  正常/部分异常/离线/无数据
                   ↑ 结束日应该在最右
```

### 改法：用显式 order，不用 contents

| 元素 | 窄屏 order | 宽屏 order |
| --- | --- | --- |
| 起始日 | 1 | 1 |
| `→` | 2（`sm:hidden`） | — |
| 结束日 | 2 | **3** |
| 图例 | 3（`w-full`） | **2**（`ml-auto`） |

`order` 是显式的，不依赖"元素在 DOM 里的位置恰好合适"。

### 这次的验证方式改了

不再只测移动端，**两端各测一次**：

| 视口 | 高度 | 起始 x | 结束 x | 结束在最右 |
| --- | --- | --- | --- | --- |
| 390px | 35px（2 行） | 33 | 116（紧跟起始日）| — |
| 768px | 14px（1 行） | 41 | **696**（行宽 686）| ✓ |
| 1280px | 14px（1 行） | 41 | **1208**（行宽 1198）| ✓ |

### 教训

评审的话值得原样记下来：**「要考虑问题之间的特性正交，不要修复了移动端，桌面端又出现了问题」**。

响应式改动天然有"按下葫芦浮起瓢"的风险 —— 因为一个类名同时影响两个断点，

**移动端 + 桌面端 + 至少一个中间断点**。

这条也适用于我之前几轮的改动 —— 回头看我验的是"移动端修好了"，

> 而一个文件里同名结构往往不止一处。** 涉及结构移动时应该按行号或加唯一锚点，
> 不能靠裸字符串。
